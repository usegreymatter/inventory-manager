# Stock Runway: agent entry

**What it is:** a free, offline reorder planner. It estimates when stock runs out and what to buy, how much and by when, from a built-in sample, a local spreadsheet/CSV (smart import), a canonical CSV bundle, or a read-only Odoo source. Forecasts are estimates. Nothing here places an order or writes to an ERP.

**Three surfaces, one set of maths:**
- Python standard-library engine and CLI: `engine.py`, `sources.py`, `csv_import.py`, `smart_import.py`, `forecast_methods.py`, `learning.py`, `health.py`, `stock_runway.py`, `tools.py`
- Hermes Desktop plugin: `desktop/plugin.js`, which **mirrors the engine in JS** (`forecast_methods.js` mirrors `forecast_methods.py`)
- Offline page: `standalone/stock-runway.html`, generated by `python3 standalone/build.py`. Edit the sources, never the output.

**What exists today vs roadmap:**
- Shipped: smart Excel/CSV import with preflight, forecast methods (Current = default; Auto = experimental opt-in), light/dark themes, local order lists (kept in the browser), settings import/export, read-only Odoo source, Python CLI.
- Roadmap only (design docs, not implemented): ERP connectors beyond CSV/Odoo, an MCP server, automatic ordering/sending, ERP write-back. See [docs/ROADMAP-CONNECT.md](docs/ROADMAP-CONNECT.md) and [docs/architecture/](docs/architecture/).

suite, install pytest as a development-only dependency in a local environment:

**Invariants:**
1. **Python/JS parity:** an engine change lands in both `engine.py` and `desktop/plugin.js`, with parity tests and a standalone rebuild.
2. **No live access in tests:** no live credentials, ERPs, network or customer data. Tests use fakes and synthetic fixtures.
3. **Forecast methods are frozen** until a scored review says otherwise. Record and score only.
4. **Missing-data gates.** Missing incoming supply stays unknown in source data and exports, but purchase estimates assume 0 incoming; check existing orders before buying. Missing or invalid stock or sales holds advice (at least 3 complete sales months are required). Missing supplier lead time uses the configured fallback (14 days by default, marked `used_default_lead`); clearing that fallback without another valid lead holds purchase advice, not the physical forecast. A supplied source lead of 0 is valid. Invalid supplied incoming holds advice.
5. **Nothing sends, writes to an ERP or spends** ([AUTOMATION](docs/architecture/AUTOMATION.md) is a proposal, not a feature).
6. Keep local evidence under ignored `.scratch/`. Secrets come from environment variables or a secret store, never from the repo.
