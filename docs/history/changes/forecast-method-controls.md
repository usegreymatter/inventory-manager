# Opt-in forecast controls

Arctic (`option-gm-b`) has one **Forecast method** settings group, with Current
(default), Auto by demand type (experimental), and named methods. Current must
preserve existing calculations. The optional industry preset is advisory: select
one to see its note, then use **Use suggested method** to explicitly apply it.
It never changes lead time, service level, buffers, cover or other order settings.
All alternatives are experimental, not validated industry recommendations.

Global JSON keys are `forecast_method` (default `current`) and `industry_preset`
(default `none`). Existing dataset-keyed persistence, strict import/export, reset
and error handling also apply to these fields. Invalid values retain previous
settings. Product report labels use `guidance.forecast_method.label`, then
`item.forecast_method.label`; the engine supplies the actual class/method and any
fallback, rather than the UI guessing from the selected dropdown.

The CLI accepts `--method` and seven `--preset` choices. Explicit `--preset` opts
into that preset's suggested method only, with an experimental stderr note.
`--method` overrides it regardless of argument order, including `--method current`.
Explicit flags override settings JSON globals. No preset silently tunes other
settings. The UI has a separate explicit apply button; the CLI flag itself is the
explicit opt-in.

## Integration and local proof

The shared pure core embeds `forecast_methods.js` verbatim (refresh via `scripts/sync_forecast_methods.py`) so
`globalThis.StockRunwayForecastMethods` exists, and normalize/validate both global
keys. CLI preset mappings come from sibling `forecast_methods.py`. No independent
math was added to the UI or CLI.

`standalone/capture-methods.cjs` exercises defaults, every method, seven advisory
presets, explicit application, reset, strict invalid imports, settings round-trip,
dataset persistence, engine-provided product labels, and desktop/phone layouts.
It writes `.scratch/methods/`; `FORECAST_PAGE` can target a scratch-built Arctic
page. It is offline and uses only built-in fully synthetic sample data, generated by `scripts/generate_sample.py` (seed 731209). Run it with the
existing Playwright/Chromium environment. See the final [verification receipt](forecast-method-verification.md) for actual execution counts.

All eight named HTML variants, the default, and the 1,000-product demo were regenerated after integration. Local browser proof uses only offline sample/synthetic data and a dedicated QA browser. No live inventory, ERP, network, purchase or deployment side effect was authorized.
