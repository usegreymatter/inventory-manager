# Settings control

The shipped Arctic page exposes a **Settings** sheet from the tools menu. Ordering, Safety stock and Alerts stay visible; Advanced EOQ inputs are collapsed. Changes recalculate locally. The phone sheet fills the viewport and scrolls independently; controls retain 44px minimum hit targets.

- **Ordering:** default lead time, months of cover, review period and buffer days. Buffer days move the order deadline earlier; they do not add units.
- **Safety stock:** service level and **Add safety stock to orders** (`include_backup_in_orders`). The preview compares the selected product's order with and without safety stock. This switch defaults to false, preserving existing orders.
- **Alerts:** Order now, Running low, Overstock and Big order thresholds.
- **Advanced:** optional order cost and annual holding cost percentage. EOQ also needs a unit cost; blank order cost disables it.
- **Supplier settings:** open Settings beside the selected product's supplier or in Supplier browsing. Overrides apply to every product with that exact supplier name.
- **Product settings:** open the product Info disclosure for overrides and effective-value provenance. Custom markers identify products using overrides.

## Precedence and resets

Each field resolves independently: **product setting > supplier setting > from file > default**. The displayed source labels use these exact names. Global lead time, review period and service level are defaults, not replacements for values already present in the file. Product overrides allow lead time (`supplier_days`), MOQ (`minimum_order`), pack size, review period, service level and unit cost. Supplier overrides allow the same fields **except unit cost**.

A blank scoped field or its Reset button removes only that override, revealing the next source. Global Reset restores that field's default. Reset all restores this dataset's defaults and clears its supplier/product overrides. Forecast and order formulas are unchanged; only their resolved inputs change.

## Persistence and portable JSON

Arctic saves settings in localStorage under a dataset fingerprint (`stock-runway.standalone.order-settings.v2:<length>:<fingerprint>`). Reopening the identical dataset restores its settings; a changed dataset can have a different key. This fingerprint is not a security identity. CSV contents are neither uploaded nor persisted. Existing v1 sample settings are accepted as a migration fallback. If storage is unavailable, changes still work for the current tab.

**Export settings** downloads validated JSON. **Import settings** replaces the current dataset's settings after strict validation; omitted fields receive defaults. Invalid/unknown fields, numeric strings, unsupported service levels and malformed JSON are rejected without changing the current settings. Browser import is limited to 2 MiB. Names are exact and case-sensitive; supplier names/SKUs in the JSON must match the target dataset. The same JSON is accepted by the Python CLI:

```sh
python3 stock_runway.py inventory.csv --all --today 2026-11-01 --settings stock-runway-settings.json
```

Explicit CLI global flags override the corresponding JSON globals; scoped product/supplier overrides still follow normal precedence. The standalone HTML itself needs no Python. Python and the Desktop JavaScript core share the same resolution/validation contract, with parity tests.

## Accepted ranges

| JSON field | Range / accepted values | Default |
| --- | --- | --- |
| `default_delivery_days` | Whole days 1–3650; null means unset | 14 |
| scoped `supplier_days` | Days 0–3650, fractional allowed | Inherit |
| `months_of_cover` | 0–36 | 2 |
| `review_days` | Whole days 0–3650 | 30 |
| `buffer_days` | Whole days 0–365 | 7 |
| `service_level` | 0.90, 0.95 or 0.99 | 0.95 |
| `include_backup_in_orders` | JSON boolean | false |
| `urgent_days` / `running_low_days` | Whole days 0–3650 | 7 / 30 |
| `overstock_months` / `big_order_months` | 0.1–120 | 6 / 6 |
| `minimum_order` / `pack_size` | 0.000001–1,000,000,000,000; at most six decimal places | Inherit / unset |
| product `unit_cost` | 0–1,000,000,000,000 | Inherit / unset |
| `order_cost` | 0–1,000,000,000,000 or null | null (disabled) |
| `holding_pct` | 0.01–100 | 20 |

Scope names are non-empty and at most 512 characters. An absent scoped entry inherits; null is not a valid scoped numeric override. Legacy persisted buffer values over 365 are capped during tolerant normalization, but strict new JSON imports reject them.
