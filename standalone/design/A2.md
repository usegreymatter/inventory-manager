# A2 — demand and stock, one monthly timeline

A local comparison candidate for an operator deciding what to order. The existing A, B, baseline and Desktop renderer are unchanged. Use a compact open layout: one blue monthly demand series (solid past, faded forecast), one neutral month-end stock line, delivery rings and a run-out flag. Teal means Fine, blue means Overstocked; status words remain visible. The chart comes first on phones; Copy order sits with the order list.

## Build and open

```sh
mkdir -p .scratch
export TMPDIR=$PWD/.scratch
python3 standalone/build.py --template option-a2
open standalone/design/option-a2.html
```

The output is a dependency-free single HTML file, usable over `file://` without a server. Edit `chart-a2.js`, `app-a2.js`, and `styles-a2.css`, then rebuild; do not hand-edit the output. These candidate-specific sources isolate A/B from this round. The shared base template and styles are read, not changed.

## Data contract

Demand bars, monthly stock points, forecast start rounding, and the fractional run-out crossing are taken from the same Desktop core/series as A. There are **no supply bars**, no new demand/stock observations and no forecast or guidance changes. All outputs embed the Desktop core and baseline helpers verbatim, including purchase-order text and membership.

Receipts in the supplied data have **month precision only**, not exact dates. One delivery ring marks each positive monthly receipt total, at that month's existing month-end stock point. Future listed receipts say **Expected delivery**, not an already-completed delivery. Its focus/hover/tap tooltip shows quantity, month and year, and explicitly says the exact date is unavailable. It must not imply an intra-month delivery day or jump. Missing historical receipt data never produces fabricated historical stock or delivery rings. Monthly stock reconstruction warnings and forecast qualifications remain accessible.

The displayed run-out date uses the existing `runout_day`; the marker retains the original fractional crossing location. The forecast excludes the suggested new order. A2 deliberately removes the extra dashed red out-of-stock segments and repeated end-of-line annotation; the stock line stays at zero and the run-out marker remains.

## Viewing controls

- **6M / 1Y / 2Y / All** select a monthly window, clamped to available months. Default/Reset is 1Y, centred around Now when bounds permit. The sample contains 18 months including forecast, so 2Y and All both show 18; 2Y never extends the forecast.
- Mouse wheel and trackpad pinch zoom around the pointer; drag pans.
- Touch pinch zooms; horizontal swipe pans. The plot captures touch gestures; the rest of the page still scrolls.
- Buttons are keyboard focusable. Focus the chart: `+`/`-` zoom, left/right arrows pan by one month, Home resets, Escape dismisses the tooltip. Delivery rings are separately focusable, with Enter/Space to show details.
- All windows snap to complete monthly intervals. SVG boundary clipping interpolates only the already-existing stock line, never adds observations.
- Six or fewer visible months show demand and positive stock value labels when there is enough horizontal room. Labels are collision-avoiding; larger windows omit them. Month ticks thin automatically.

```sh
python3 -m pytest -q
node --test tests/desktop.test.mjs tests/planning.test.mjs tests/safety.test.mjs tests/standalone.test.mjs
# Use an already installed Playwright, never install for this candidate.
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.js \
CHROMIUM_EXECUTABLE=/absolute/path/to/isolated/chromium \

```

The A2 parity tests render Desktop's actual Chart and compare demand values, invert its stock polyline geometry back to monthly coordinates/values, and check A2's displayed points/delivery counts at four presets and three widths for every sample item plus missing-history, fractional-start and already-empty edges. Build drift tests include A2; the existing exact core/helpers/guidance/PO/ERP fixture tests also run against A2.

`capture-a2.cjs` checks real presets, clamp boundaries, labels and tick density, desktop wheel/drag, trackpad-style wheel pinch, keyboard controls, CDP touch pinch/swipe, receipt focus/mouse/tap tooltip, theme appearance, horizontal overflow, label bounds/overlap, no console/page errors, and no HTTP(S) requests. Six exact-viewport screenshots plus the machine-readable report are written to `.scratch/design/`; these are local Chromium evidence, not Safari/physical-device/hosted/ERP or purchasing proof. The long page intentionally scrolls below the viewport; screenshots are not full-page exports.
